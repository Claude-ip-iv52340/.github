<p>"几个号同时挂着会不会互相牵连"，这句话在群里问了无数遍，答案几乎都是经验之谈。其实这件事可以做对照实验：分三组，只改一个变量，跑两周，看指标差异。这篇把实验设计、观测指标、记录方式、结果解读完整写一遍，数字是小样本示意，重点在方法——照着做一遍，你手上这批号的真实情况比任何人的经验都准。</p>

<h2>一、实验怎么分组，只改一个变量</h2>
<p>对照实验的价值在于"只改一件事"。一次改三个变量，最后不知道是谁起的作用。</p>
<h3>三个组的设置</h3>
<p>A 组：机房静态出口，多个号共用一个浏览器配置目录。B 组：静态住宅出口，多个号共用一个浏览器配置目录。C 组：静态住宅出口，一号一个配置目录、一套指纹。每组五个号，共十五个号，用途统一为日常对话加每周一次订阅页访问。</p>
<h3>必须控住的变量</h3>
<p>五个：操作时段（都在本地上午十点与晚上八点）、单日操作量（每号三十到四十条对话）、设备（同一台机器，避免硬件差异）、IP 地区（同一个国家）、以及操作人（同一个人的固定操作习惯）。这五项任一不同，结果就会被污染。</p>
<h3>先跑三天基线再开始记</h3>
<p>新环境上线后前一两天数据偏高是正常的，前三天只跑不记，从第四天开始正式记录，这样避免把"环境刚建立"的波动当成组间差异。</p>

<h2>二、观测四个指标，记录要具体</h2>
<p>指标太多记不住，四个够用，而且都能从日常操作里顺手记下来。</p>
<h3>四个指标的定义</h3>
<p>验证弹窗次数：每百次操作触发验证的次数，按周汇总。会话中断次数：单次操作过程中出口变化或连接断开，导致需要重新登录的次数。P95 延迟：用 <code>mtr -rwzbc 100 目标地址</code> 每天测两次，取当周 95 分位。登录成功率：首次尝试即成功的比例。</p>
<h3>记录方式</h3>
<p>一张表，行是日期，列是组别乘指标，每天两分钟填完。不要用事后回忆补数据，回忆会把异常抹平，实验就白做了。检测站截图按组存放，命名用"组别-日期-号序号"，后面查证方便。</p>

<h2>四、结果怎么读：三个反常识的地方</h2>
<p>数据出来以后，容易被误读的地方有三处。</p>
<h3>延迟最低的组，体验不一定最好</h3>
<p>A 组机房线的 P95 延迟通常最低，因为机房到骨干网路径短。但它的验证次数最高，一次验证要多花三到五分钟，把延迟优势全吃掉了。所以评估不能只看延迟，要看"有效操作时间"——总时长减去被验证和重登占用的时间。</p>
<h3>换环境比换线路更能降验证</h3>
<p>B 组和 C 组的出口相同，只有环境隔离不同，验证次数差了近三倍。这说明在出口已经合格的前提下，环境隔离的收益明显大于继续优化线路。很多人反复换服务商，问题却一直在环境上，换了也白换。</p>
<h3>第一次验证出现的天数，是最灵敏的指标</h3>
<p>比总次数更早给出信号。C 组第 8 天才出现第一次验证，A 组第 2 天就出现，说明前者的环境更容易被接受。用这个指标做早期判断，不用等两周就能看出方案对不对。</p>

<h2>五、把这套实验搬到自己号上</h2>
<p>不必完全照抄十五个号的规模，缩小版同样有效。</p>
<h3>最小可复现版本</h3>
<p>每组两到三个号，跑七天，只记两个指标：验证次数和会话中断次数。虽然样本小，但组间差距如果达到两倍以上，结论就足够指导决策。重点是控住变量，不是样本量。</p>
<h3>结论的复用边界</h3>
<p>实验结论只对你测的那批地址段和那个平台有效。换服务商、换目标平台、换地区，都要重新跑一遍。别把一次结论当成永久规律，行业里地址段质量变化很快，三个月前的数据参考价值会明显下降。</p>
<h3>把实验变成例行工作</h3>
<p>每季度跑一次小规模对照，记录变化趋势。这项工作半天到一天，能提前发现"这批线开始变差"的信号，比等到大面积验证再去救火划算得多。</p>

<h2>常见问答</h2>
<h3>五个号一组，样本会不会太小？</h3>
<p>答：对绝对数值来说偏小，对相对差异够用。如果两组验证次数差两倍以上，小样本也能看出趋势。要精确到百分比，就需要更大的样本和更长的周期，多数团队没必要做到那个精度。</p>
<h3>共用浏览器目录到底影响什么？</h3>
<p>答：影响 Cookie、本地存储、缓存和部分指纹项。多个号共用，等于在同一台"设备"上留下多份登录痕迹，服务端很容易把它们归到一组。这正是 B 组和 C 组差异的主要来源。</p>
<h3>实验期间能不能做别的事？</h3>
<p>答：尽量不要在实验号上做计划外操作。一旦有人临时拿实验号跑批量任务，数据就废了。分组时就标记清楚，实验期内这些号只按脚本规定的方式使用。</p>
<h3>结果和预期相反怎么办？</h3>
<p>答：先查变量有没有控住，尤其是操作人和操作时段。变量没问题，就接受结果并调整方案。实验的意义就是修正预期，不是验证已有结论。</p>
